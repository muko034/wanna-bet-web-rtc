# Internationalization

## Render user-facing copy through `useT()`

A component never holds a literal user-facing string. It calls `const t = useT()` and renders `t('screen.element')`, including placeholders and button labels. Copy then lives in one dictionary per language and switches with the language toggle.

```tsx
const t = useT();
<button class="vb-cta" type="submit">{creating ? t('createRoom.submitting') : t('createRoom.submit')}</button>
```

## Resolvers and state carry keys, not text

Resolvers, lookup tables and component state that describe copy hold a `MessageKey`, or a `Message` (`{ key, params }`) when the text needs values. They never hold English text. The component calls `t(message.key, message.params)` at render, so a language change re-renders correctly and resolver tests assert on stable keys.

```ts
const ERROR_MESSAGES: Record<..., MessageKey> = { 'room-full': 'joinRoom.error.roomFull' };
const [rosterNotice, setRosterNotice] = useState<{ messages: Message[]; key: number } | null>(null);
```

## Dictionary shape: one key set, typed parity, shared keys

`en` defines the keys and `MessageKey` is derived from it. Every other dictionary is typed `Record<MessageKey, string>`, so a missing translation fails to compile. Name keys `screen.element` in camelCase (`joinRoom.error.roomFull`); fill values with `{name}`-style placeholders supplied through `params`. When two screens show the same copy, share one key (`form.namePlaceholder`, `joinRoom.retry`) instead of duplicating it.
